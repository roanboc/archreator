Human-first architecture method

Architecture people can understand and AI can build from.

ArChreator turns what people know about an initiative, solution, domain or enterprise into a small, navigable model. Plain language leads; ArchiMate precision and executable workflow remain underneath.

Start with one repository Read the method

The operating principle

Keep the project small.
Keep the method rigorous.
  • No empty layer tree
  • No persisted graph to keep in sync
  • No blanket approval sequence
  • No agent-only black box

Two first-class routes

The same model serves different readers.

Independent builder

Explain the business. Get only the architecture you need.

You bring the users, outcomes, constraints and implementation. ArChreator selects the right discovery route, exposes material gaps, and keeps the model understandable without teaching you an architecture framework first.

Enterprise architect

Navigate the structure directly. Follow every relationship.

Standard areas, stable identifiers, ArchiMate types, declared relationships, ownership and source links remain visible. Use the repository or on-demand portal; an agent is helpful, never the only doorway.

A method, not a preprompt

Every workflow has a contract.

ArChreator adapts the Agent Instruction Protocol to readable Markdown and binds it to a supplier-input-process-output- customer process model. That makes missing work and hidden judgement visible.

Procedures

State when to run and when not to, invariants, inputs, outputs, judgement, conditional human checkpoints, handoffs, anti-patterns and completion tests.

Document templates

Rulebooks

Preserve clear writing, standard architecture navigation and breadth-first, depth-on-pain process and capability modeling.

One source, created lazily

A recognizable structure without placeholder volume.

Every repository starts with one front door. An area folder appears only when the model owns real content there; otherwise the front door says External, Out of scope, or names the specific Gap.

EnterpriseShared direction, capabilities and constraints
DomainOwned outcomes, information and exposed contracts
SolutionBehavior, components, interfaces and runtime

One fact has one owner. A lower model refines an exposed contract; it does not copy its parent.

Every page states its location. Each populated hierarchy level has a file, and every child names its parent in human language as well as in its stable ID.
