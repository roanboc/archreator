archreator

Get started

archreator is a plugin for your coding agent. Install it, say what you want to model, and the method takes over from there. Pick your agent below — every route lands in the same place.

Claude Code GitHub Copilot Codex CLI Gemini CLI No agent yet

1 · Install it

Claude Code terminal, desktop app, VS Code and JetBrains

Inside any session, two slash commands:

/plugin marketplace add roanboc/archreator
/plugin install archreator@archreator

Start a new session afterwards so the skills are picked up. Update later with /plugin update archreator@archreator.

GitHub Copilot Copilot CLI, VS Code and the Copilot app

From your shell:

copilot plugin marketplace add roanboc/archreator
copilot plugin install archreator@archreator

The same two steps work as /plugin marketplace add and /plugin install inside a Copilot session. Confirm with copilot plugin list; update with copilot plugin update archreator.

Codex CLI terminal, IDE extension and the Codex app

From your shell, or as slash commands inside a session:

codex plugin marketplace add roanboc/archreator
codex plugin install archreator@archreator

Start a new session before using the skills — Codex reads its plugin list at launch. /plugins opens the browser if you would rather install from there.

Gemini CLI terminal

Gemini installs an extension from a repository root rather than a subdirectory, so it takes the skills directly instead of the plugin. Clone the repository once and run the installer: 

git clone https://github.com/roanboc/archreator.git
cd archreator
python3 plugins/archreator/scripts/install_skills.py

That copies the eighteen skills into ~/.agents/skills/, the directory every host reads. Restart Gemini so it rescans. Re-run the same command after a git pull to update.

The installer works for Claude Code, Copilot and Codex too, if you would rather not install a plugin. Add --repo to put the skills in the current project's .agents/skills/ instead of your home directory, or --dry-run to see what would land. It ships the skills and not the project files — those still arrive on the first run, below.

2 · Run your first session

There is nothing to configure and no command to memorise. Say what you want to model, in your own words — set up architecture for this repo, or I want to model my consultancy — and the establish-project skill recognises the situation and starts.

  1. It asks what the project is. One application, one organization, or an enterprise large enough to split into business lines. Answer in a sentence.
  2. It picks a modeling depth and tells you which. Depth 1 is a single application with a light strategy layer; depth 2 is one organization; depth 3 splits the model into domains. It is a starting posture, never a ceiling — changing it later is a normal initiative.
  3. It writes eleven files into your repository. The entry point that records the depth, your model's front page, and two validators that run on plain Python with no network. Layer folders appear when they have something to hold — until then the front page says, per layer, whether it is here, somewhere else, out of scope, or a gap.
  4. It hands off to discovery. Strategy and business architecture first, always — that is the rule the whole method turns on. Nothing gets built before you approve it.

What lands in your project

PathWhat it is
AGENTS.md The entry point every agent reads: the rule that governs everything else, and the declared modeling depth
CLAUDE.md · GEMINI.md One line each, importing AGENTS.md, so a host that reads only its own filename still finds it
architecture/ The six numbered layers — strategy through technology — plus scope/, one document per initiative, and decisions/
scripts/ Two validators: relative links resolve, and element-ID references resolve. Run them before every push
README.md · CONTRIBUTING.md Your project's own front door, and who the Requester, Agent and Reviewer are

Nothing else. The skills do not touch your files until you ask them to, and no code is generated before a gate is approved.

Starting without an agent

The scaffold is plain markdown and stands on its own — eleven files, two of them validators that need nothing but Python. Copy plugins/archreator/scaffold/ into a new repository and fill it in by hand, then install the skills whenever you want an agent to take over. The method is the same either way; the skills only make an agent follow it faithfully.
