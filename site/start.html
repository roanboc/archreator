Get started

Begin with one question and one front door.

Install the plugin, describe the initiative in your own words, and let ArChreator create only the context that is useful now.

01

Install the plugin

Choose the host you use. The repository is the same source for every supported agent.

Claude Code

/plugin marketplace add roanboc/archreator
/plugin install archreator@archreator

GitHub Copilot

copilot plugin marketplace add roanboc/archreator
copilot plugin install archreator@archreator

OpenAI Codex

codex plugin marketplace add roanboc/archreator
codex plugin add archreator@archreator

Another skill-capable agent? Make the ten folders under plugins/archreator/skills/ available through its skill mechanism. Copy the minimal scaffold only when the repository has no equivalent entry files.

02

Describe the need naturally

Help me model this initiative clearly.

The model-context procedure inspects evidence before it interviews you. It names the model level and authority, chooses only the relevant business-model, strategy or landscape discovery route, and creates the smallest useful current model.

  1. Set the boundary.Enterprise, Domain or Solution; purpose, owner, parent and exclusions.
  2. Load only relevant discovery.Customers and value, strategy, or the current estate—not all three by default.
  3. Resolve real uncertainty.A person is asked only when a material gap or inconsistency changes the model.
  4. Write and verify current context.Self-locating pages, explicit parents, clear prose, useful visuals and traversable relationships.
03

Know what lands in the repository

Always

  • AGENTS.md and host pointers
  • architecture/README.md as model boundary, status and navigation

Only when useful

  • Standard area folders with real locally owned content
  • architecture/decisions/ for durable material rationale

Only when requested

  • Briefs, scopes and individual PDFs under .archreator/work/<run>/
  • The static portal under .archreator/work/portal/

No empty layer tree, SQLite projection, whole-model PDF, portal configuration or publishing workflow is copied into a customer repository.

04

Use the model by asking for an outcome

Understand

“Explain how orders are handled to a business reader.”

Direct answer, understanding brief or portal—only as requested.

Assess

“What would changing the order service affect?”

Current relationships traced in both directions, with unavailable context stated.

Plan

“What should this become, and in what order?”

Baseline, target outcomes, material gaps and dependency-led sequence.

Deliver

“Implement this change and keep the architecture true.”

Impact, implementation, proportionate verification and current-context refresh.

05

Use the small runtime when repetition helps

The runtime reads current Markdown on every command. It does not maintain a database or generated graph.

python plugins/archreator/scripts/archreator.py --repo . check
python plugins/archreator/scripts/archreator.py --repo . trace ACMP1 --direction both --depth 2
python plugins/archreator/scripts/archreator.py --repo . work --name impact-order-service
python plugins/archreator/scripts/archreator.py --repo . portal
python plugins/archreator/scripts/archreator.py --repo . pdf --kind brief .archreator/work/impact-order-service/impact-order-service.md

PDF export accepts only a scope or brief inside .archreator/work/. The complete architecture is consumed in the repository or portal.
